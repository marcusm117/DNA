\section{Introduction}
% - What problem: faithful formalization of Euclid proofs; gap vs prior (LeanEuclid).
% - Our idea in 2-3 sentences. Contributions as a bulleted list.
Given a natural language (NL) proof, a faithful formalization has many applications; it can be used to check the reasoning of an AI, it can be used to help expert mathematicians verify a large proof, and it is a necessary step to complete textbook level autoformalization. However, the notion of what a faithful proof even is, is not well addressed, nor how we can general faithful proofs. In order to address this, we give a set of \faithfulcriteria a proof must have, that any faithful methodology must ensure, and developped an algorithm \methodname, that guarantees these criteria are satisfied.

The focus of our study was on Euclidian geometry, which is considered formal, so being faithful should not introduce many soundness issues, and an existing system exists \citep{murphy_autoformalizing_2024} and \citep{avigad_formal_2009} helping us get started.

Thus we build off of the Book 1 proofs done by \citet{murphy_autoformalizing_2024}. We address two issues with this work. The first, is that we believe these proofs are not faithful. They do not satisfy our proposed \faithfulcriteria. The second, is that the work of \citet{murphy_autoformalizing_2024} takes very long to compile the formal proof and sometimes may not even compile. \citet{min_divide_2026} had to comment out 10 propositions because of this, and we were unable to compile some of the proofs in under 20 minutes. So we also ensure our methodology generates proofs that compile much faster.

We ran our methodology through Books 1, 2, and 3, generating \numproofs faithful proofs of Euclid's Elements.

\section{Methodology}

The goal of our methodology is to generate formal (Lean) proofs \emph{guaranteed} to satisfy \cref{tab:conditions} with minimal oracle\footnote{We use human experts for this, but it could be a very capable LLM for example} and LLM reliance, since oracle time is the most expensive, while LLM usage also costs money.

Of the conditions in \cref{tab:conditions}, \methodname only requires the oracle the task of \emph{reviewing} \atomicity, and \atomicfaithfulness. The overall methodology is the LLM first splits up the NL proof into what it thinks are sentences satisfying \atomicity. A script checks \coverage is satisfied, and if not, the LLM is automatically prompted to fix the issue. Once the LLM is done with this, it is tasked with \atomicfaithfulness, the task of translating each NL assertion/assumption into formal lean. Then the LLM runs a script that checks \textit{partially} checks \citcond. Partially because some citations are intended to be used to proove this sentence's assertion, but at this point we only translate sentences, not prove them, so they are left with \texttt{sorry}. Finally, the oracle reviews this, ensuring \atomicity and \atomicfaithfulness are satisfied. If not, the oracle provides feedback to the LLM, which is prompted to fix the issue. This process continues until the oracle is satisfied, and concludes the mapping phase.

Once mapping phase is complete, we save the sentence, the split of assertion/assumption of this sentence, and its mapping to Lean in a file the LLM is not allowed to write to. So now, we need to fill in the \texttt{sorry}'s left in mapping phase (ensuring \soundness), and prove things citing the correct propositinos ensuring \citcond. This process is done entirely using LLM + Scripts.

\subsection{Proving Phase}
While the other two phases are straight forward, this phase is tricky because compile times are long. Some issues are for example
\begin{enumerate}
	\item If we have many sentences, and each takes a while to compile, then editing a later sentence will require all previous steps to recompile, accumulating massive amounts of wall time (sometimes hours or days)
	\item If the current subgoal cannot be closed due to SMT-timeout, where do we even begin?
	\item Assuming we had some idea of what where to begin a proof, how do we know this path is correct without compiling other parts of the proof to save wall time?
\end{enumerate}

To address item 1, we do two things. First, we subgoals into various lemmas, and these lemmas into other sub-lemmas. Second, we leave as much as we can as \texttt{sorry}, and only filling these \texttt{sorry}'s in when necessary, so that compile times are fast. Only at the end, in the wiring phase do we know that replace the \texttt{sorry} with actual lemma calls (though at this stage we are certain this wiring must be correct).

To address item 2, we introduce a database with various search features to help the LLM get started.
