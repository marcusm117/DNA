\section{Introduction}
% - What problem: faithful formalization of Euclid proofs; gap vs prior (LeanEuclid).
% - Our idea in 2-3 sentences. Contributions as a bulleted list.
Given a natural language (NL) proof, a faithful formalization has many applications; it can be used to check the reasoning of an AI, it can be used to help expert mathematicians verify a large proof, and it is a necessary step to complete textbook level autoformalization. However, the notion of what a faithful proof even is, is not well addressed, nor how we can general faithful proofs. In order to address this, we give a set of \faithfulcriteria a proof must have, that any faithful methodology must ensure, and developped an algorithm \methodname, that guarantees these criteria are satisfied.

The focus of our study was on Euclidian geometry, which is considered formal, so being faithful should not introduce many soundness issues, and an existing system exists \citep{murphy_autoformalizing_2024} and \citep{avigad_formal_2009} helping us get started.

Thus we build off of the Book 1 proofs done by \citet{murphy_autoformalizing_2024}. We address two issues with this work. The first, is that we believe these proofs are not faithful. They do not satisfy our proposed \faithfulcriteria. The second, is that the work of \citet{murphy_autoformalizing_2024} takes very long to compile the formal proof and sometimes may not even compile. \citet{min_divide_2026} had to comment out 10 propositions because of this, and we were unable to compile some of the proofs in under 20 minutes. So we also ensure our methodology generates proofs that compile much faster.

We ran our methodology through Books 1, 2, and 3, generating \numproofs faithful proofs of Euclid's Elements.

\section{Methodology}

The goal of our methodology is to generate formal (Lean) proofs \emph{guaranteed} to satisfy \cref{tab:conditions} with minimal oracle\footnote{We use human experts for this, but it could be a very capable LLM for example} and LLM reliance, since oracle time is the most expensive, while LLM usage also costs money.

Of the conditions in \cref{tab:conditions}, \methodname only requires the oracle the task of \emph{reviewing} \atomicity, and \atomicfaithfulness. The overall methodology is the LLM first splits up the NL proof into what it thinks are sentences satisfying \atomicity. A script checks \coverage is satisfied, and if not, the LLM is automatically prompted to fix the issue. Once the LLM is done with this, it is tasked with \atomicfaithfulness, the task of translating each NL assertion/assumption into formal lean. Then the LLM runs a script that \textit{partially} checks \citcond. Partially because some citations are intended to be used to proove this sentence's assertion, but at this point we only translate sentences, not prove them, so they are left with \texttt{sorry}. Finally, the oracle reviews this, ensuring \atomicity and \atomicfaithfulness are satisfied. If not, the oracle provides feedback to the LLM, which is prompted to fix the issue. This process continues until the oracle is satisfied, and concludes the \mapstage.

Once the \mapstage is complete, we save the sentence, the split of assertion/assumption of this sentence, and its mapping to Lean in a file the LLM is not allowed to write to. This frozen mapping is the contract the \fillstage must satisfy without being able to weaken it: fill in the \texttt{sorry}'s left in the \mapstage (ensuring \soundness) and prove each citing the correct propositions (ensuring \citcond), entirely using LLM and scripts.

\subsection{\fillstage}
Naively, one hands the mapped file --- Lean with one \texttt{sorry} per sentence --- to an LLM and asks it to fill them in. In many domains this local gap-filling works. Here it fails structurally: a \texttt{sorry} is not a gap but an independent theorem. Euclid reasons informally; our logic is System E, which he never used. A sentence like ``therefore $AB=CD$ [Prop.~I.4]'' is not one tactic call --- discharging it in System E requires re-establishing figure facts Euclid reads off the diagram and never states (betweenness, side-of-line, distinctness), which the SMT backend needs as explicit hypotheses. Each sentence is thus its own multi-step proof. Worse, the checker gives no signal on failure: \texttt{euclid\_finish} closes a \emph{small} explicit step by SMT but times out on anything larger, returning neither counterexample nor partial progress, so restate-and-rerun thrashes.

These two facts --- every \texttt{sorry} is a theorem, the verifier is a timeout oracle --- force three constraints the \fillstage is built around. \textbf{Isolation:} each sentence is proved as a standalone lemma in its own file, importing only System E and the propositions it cites, so editing sentence $k$ never recompiles $1..k{-}1$. \textbf{Bounded decomposition:} every SMT query must close under a fixed cap; a step that exceeds it is recursively split into sub-lemmas until each leaf closes --- caps are never raised, work is subdivided. \textbf{Seeding:} to start a stuck goal we give the LLM a database of System-E facts indexed by what they conclude and consume, and it drives a fixed sequence of scripts that certify each lemma's proof cone in isolation, so a wrong path is cheap to discard. Throughout, the mapped sentences stay \texttt{sorry}; a final mechanical wiring step substitutes the proven lemmas, and by construction the wired proof compiles.

\begin{algorithm}[t]
\caption{\textsc{Fill}(node $n$) — recursive; every other node stays \texttt{sorry}.}
\begin{algorithmic}[1]
\IF{SF($n$) fails}      \STATE fix claim \COMMENT{$n$ is the wrong thing to prove}
\ELSIF{SP($n$) fails}   \STATE fix signature \COMMENT{a hypothesis isn't suppliable}
\ELSIF{P($n) \le 30$s}  \STATE mark $n$ proved
\ELSE                    \STATE split $n$ into sub-nodes; \textsc{Fill} each \COMMENT{timeout}
\ENDIF
\end{algorithmic}
\end{algorithm}
